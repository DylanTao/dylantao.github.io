## Exact lighting values, smaller transfer

The new contact code initially exceeded the unchanged four-MiB first-view gate
by 373 bytes. Version 2 of the official light-cache producer writes the existing
float64 transport and float32 moments as little-endian base64 bytes. The runtime
still accepts legacy decimal snapshots, rejects corrupt packed data before any
live mutation, and retains the original live-bake fallback.

All 47,616 transport numbers and 32,768 moment numbers equal the preceding
accepted cache exactly. Probe positions, validity, relocation and physical
configuration are exact. An independent reader compares 1,536 CPU samples and
every float32 array supplied to the position, moment and coefficient textures
across three lighting states; all match and restoration traces zero visitor rays.
The separate native GL fixture restores packed data and produces the same linear
RGBA8 central-sample result as its live-baked field. The official bake
still collects 620,345 accepted plus 116,123 skipped triangles before ROI. No
geometry, drawing detail, light capacity or probe count is reduced.

The cache changes from 792,609 to 711,629 JSON bytes, and from 269,057 to 182,783
bytes using the gate's level-six gzip accounting: 86,274 bytes saved. The cache
and its descriptor come only from `node bin/bake_coastal_static_light.cjs`.
Versioned imports deliver the compatible reader and contact modules to returning
browsers. The final production product, source bindings, full checks and browser
receipts are retained beside this review.
