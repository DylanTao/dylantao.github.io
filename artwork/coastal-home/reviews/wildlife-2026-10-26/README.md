```powershell
node --test test/wildlife-neighbors.test.mjs test/wildlife-scene.test.mjs test/wildlife-delivered-contact.test.mjs test/wildlife-perch-contact.test.mjs
$env:NO_WEBSERVER='1'
$env:VISUAL_BASE_URL='http://127.0.0.1:4105/al-folio'
$env:VISUAL_PORT='4105'
npx.cmd playwright test --config test/visual/public.config.js desk-scene.spec.js --grep 'delivered paws and gull wings' --workers=1
```

The URL must be an intentionally owned complete build using the same source and model bytes. The retained `proxy.py` describes this worker's temporary source routing; it is evidence of the local fixture, not a production server. Ordinary runs and CI use the repository's own delivered assets. When reading the coordinator's spec from a worker with its own node_modules, launch the coordinator's Playwright CLI as well; mixing the two installed test instances fails discovery before any browser runs. That failed launcher log is retained. The coordinator runs production-cache/build/scene/CI/live acceptance after integration.
